# MSHost Talk Desktop

Windows x64, версия `2.3.4-alpha.3`. Основа — официальный Nextcloud Talk Desktop
`v2.3.4`, commit `63f365edc23e45fd53c53b29839f599186b2460e`.

Исходники MSHost публикуются в ветке `mshost` собственного
[форка](https://github.com/BigShiShKa/mshost-talk-desktop/tree/mshost).
`main` сохраняет более новый upstream; это другая база, чем текущая сборка.

Это отдельное приложение для разговоров и звонков. Файловый MSHost Cloud
не заменяется. Стандартный интерфейс и механизм звонков upstream сохранены.

## Брендинг

- Имя приложения, EXE, установщик и ярлыки: `MSHost Talk`.
- Сервер по умолчанию: `https://cloud.mshostcloud.org`; адрес можно изменить.
- Конфигурация: `.overrides/build.config.json`.
- Windows AppID: `org.mshostcloud.talk`; Squirrel AppID: `MSHostTalk`.
- Профиль: `%APPDATA%\MSHost Talk`, отдельно от Nextcloud Talk и MSHost Cloud.
- Проверка обновлений официального Nextcloud Talk отключается штатной логикой
  брендированных сборок. Обновления MSHost устанавливаются вручную.
- Логотип Talk: белая монограмма **MT** (MSHost Talk) в облаке с градиентным
  бирюзово-сине-фиолетовым контуром. Исходник `branding/talk-logo-mt.svg` состоит
  из векторных контуров; шрифты и встроенные растровые изображения не требуются.
  Из него генерируются иконки EXE/трея, графика установщика и экранов приложения.
- Лицензия AGPL-3.0-or-later и уведомления upstream сохранены.

## Сборка

### Исправления безопасности alpha.3, 14 ноября 2026

- В навигации маршрут сериализуется через `JSON.stringify`; проверяются origin
  инициатора и полностью привязанные допустимые пути. Подстановка JavaScript
  из фрагмента ссылки закрыта; такой же способ передачи строк применён к ID
  элемента в обработчике разрешений.
- Пароль приложения хранится только в main process; на Windows файл
  `%APPDATA%\MSHost Talk\credentials.enc.json` защищён `safeStorage`/DPAPI.
  Renderer получает только сервер и имя входа, без пароля. IPC миграции доступен
  только окну welcome, а завершение входа проверяет окно-источник.
  WebSocket-уведомления используют штатный pre_auth с временным токеном;
  основной app password не передаётся JavaScript-клиенту уведомлений.
- Старый JSON автоматически мигрирует при запуске: main process шифрует пароль,
  после чего renderer перезаписывает запись localStorage без него. Выход удаляет
  файл хранилища и отключает добавление Authorization к запросам. При недоступном
  безопасном шифровании пароль открытым текстом не сохраняется.
- Перезапись localStorage не гарантирует физического удаления старых записей
  из журналов Chromium или прежних резервных копий профиля. DPAPI не защищает
  от вредоносного процесса с правами того же Windows-пользователя.
- Экспорт исходников ограничен точным перечнем `branding/source-files.json`;
  неожиданные файлы, ссылки за пределы корня и приватные ключи останавливают экспорт.

Регрессии из корня репозитория: `node branding/test-security.cjs`,
`node branding/test-credentials.cjs`; реальный изолированный Electron/DPAPI:
`node_modules/electron/dist/electron.exe branding/smoke-security.cjs`.
Проверки используют искусственные данные, не настоящий аккаунт.

Для доверенной Authenticode-подписи задать `WINDOWS_SIGN_PARAMS` и запускать
с `-RequireSignature`. В текущем окружении сертификат издателя не найден;
alpha.3 остаётся неподписанной, этот пункт ревизии не закрыт.
[Политика обновлений и ограничения](SECURITY-MAINTENANCE.md).

Нужны Node.js 24, npm 11, Python 3, Windows x64 и доступ к npm/GitHub.
Версии зависимостей закреплены в `package-lock.json`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\branding\build-windows.ps1 -InstallDependencies
```

Lifecycle-скрипты зависимостей выключены при `npm ci`; установочные скрипты
Electron, esbuild и выбора архитектуры 7-Zip для Squirrel запускаются явно. В этой среде автоматическая подготовка
git-зависимости npm завершалась ошибкой поиска `node` и зависанием родительского
процесса. Причина — лишняя кавычка в PATH. Скрипт сборки удаляет кавычки из PATH
только на время своего процесса и восстанавливает значение после завершения.
Системный PATH не меняется. Проверка integrity lock-файла не отключается.

`CHANNEL=stable` выбирает штатный путь упаковки и формирования версии без проверки
совпадения upstream git-тега с версией форка; версия самого приложения остаётся
`2.3.4-alpha.3`. Это не заявление о стабильности сборки MSHost.

Без `-InstallDependencies` используются уже установленные зависимости.
Упакованное приложение: `out/MSHost Talk-win32-x64`.
Установщик Squirrel: `out/make/squirrel.windows/x64`.
Скрипт экспортирует установщик, ZIP приложения, архив исходников и SHA-256
в `D:\MSHost\Builds\TalkDesktop\dist\2.3.4-alpha.3`.

ZIP содержит всю папку приложения: один EXE без ресурсов не работает.
Запуск из ZIP после распаковки не требует установки, однако профиль сохраняется
в AppData, а не рядом с EXE.
